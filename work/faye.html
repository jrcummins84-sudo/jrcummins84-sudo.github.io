Independent product project

Faye

A personal AI operating system designed to reduce administrative work by connecting context, memory, reasoning, governed actions and a calm interface.

Role: Product owner / AI systems designer / AI-assisted application developerPlatform: Android · Kotlin · Jetpack ComposeStatus: Evolving personal project

The product premise

Faye began with a practical question: what if an AI assistant managed more of the system around a decision instead of waiting for another prompt?

The project treats AI as an operating layer across planning, memory, projects, communications, personal context, finances, household administration and decision support. The goal is not more chat. The goal is less clerical work and clearer decisions.

A system, not a chatbot

The product is designed around five connected layers: context → memory → reasoning → governed actions → interface. State, evidence, action boundaries and verification are treated as product requirements rather than hidden implementation details.

Conclusion first. Decision second. Evidence third. Machinery almost never.Faye is designed to keep complexity in the system and clarity in the interface.

Design evolution

The visual direction was developed through repeated concept rounds and usability audits before converging on a dark, editorial interface with conventional navigation, restrained signal color and clear state communication. The public case study now emphasizes the functioning product rather than concept-board imagery.

From engineering shell to product

Version 20.1 replaced an older HOME / ASK / ACTIVITY / CALENDAR shell with a broader product model organized around Home, Areas, Projects and Activity, while keeping calendar and system-maintenance capability available contextually.

The redesign also moved Ask out of primary navigation and introduced a persistent global command dock: compact while idle, richer when needed.

Governed autonomy

Faye is intentionally designed so convenience does not erase control. Planning, approvals, action execution, trust policy, provenance and verification remain separate concerns. The product distinguishes a recommendation from an action, an action from execution, and execution from verified completion.

Safety principles

Ambiguous commands fail closed. Stale targets are not allowed to silently become active again. Reversible actions are preferred. Source problems should surface their impact without inventing state.

Release discipline

Faye became a practical laboratory for product ownership and software quality. The project uses source audits, regression checks, backend unit/integration tests, build gates, explicit release criteria and physical-device acceptance rather than treating a compiling prototype as “done.”

Physical-device checklists cover upgrade/migration behavior, stale-target safety, command-history privacy, semantic regressions, navigation, Android compatibility and on-device ML behavior.

What this demonstrates

Product strategy · AI systems thinking · Android product architecture · UX / information architecture · governed automation · QA · release management · iterative design.

Faye is my first major application-building project, but it follows the same through-line as my learning-technology work: understand the complicated system, model it clearly, then make it easier and safer to use.
